# Wave 13c — cross-package types from a bare luarocks tree (#30)

Owner pre-release burn-down; queued behind 13b (shared crates). Design decision + implementation: harvest LuaCATS annotations from installed rock sources so a bare `luarocks install --tree lua_modules` yields visible, checked signatures without a defs package. The documented sharp edge goes away.

## Comments

- **opus-13c** (2026-07-29T23:25:00.000Z): Shipped on `sprint/w13c-rock-tree-types` (5 commits, pushed). A bare `luarocks install --tree lua_modules <rock>` now types the rock with zero manifest declaration. **Design** (decisions/09-rock-tree-type-harvest.md, Accepted): Distribution walks the tree path-only — `crates/luabox-manifest/src/layout.rs:494` `collect_rock_sources`, path-sorted, module name the inverse of the bundler's mapping (`crates/luabox-manifest/src/layout.rs:539` `rock_module_name`), version dir shared with resolution via the now-public `crates/luabox-bundle/src/resolve.rs:80` `rocks_version_dir`. Semantics reduces each source to a *surface* — `crates/luabox-types/src/rocks.rs:161` `harvest_file` runs `module_surface`, which returns a surface and no diagnostics, so there is no channel for a vendored body's type error to become project output; #16's rule that vendored code is never typechecked is untouched. Three skip rules: no `---@` anywhere → skipped before parsing (not just cheap — an unannotated module's export is a table of `unknown`s whose shape is whatever its top-level assignments reveal, so harvesting it could only manufacture undefined-field noise); annotated but unparseable → skipped whole, LSP-log note only (`crates/luabox-lsp/src/server.rs:341`); flat `lua_modules/<name>/` layout → not harvested at all, existing defs route unchanged.
- **opus-13c** (2026-07-29T23:25:00.000Z): **Precedence** needed a new merge, and this is the one judgement call worth flagging for review. `Ambient::with_project_types` unions a class's members across declarations (luals parity), which would have meant a project's own `mylib.Point` silently gaining the rock's extra fields — defeating the escape hatch. Added `crates/luabox-types/src/defs.rs:139` `with_rock_types` (backed by `crates/luabox-types/src/env.rs:452` `insert_unclaimed_types`): whole-declaration first-wins, applied *after* the project layer, so stdlib/`[types] defs`/project sources all beat a rock outright — replaced, not merged. Among rocks it is **silent** first-wins in path order, deliberately diverging from the `LB0307`/`LB0310` defs-collision warnings: the user declared neither side of a rock-vs-rock clash and cannot edit vendored code, so the warning would be unactionable noise on a zero-config feature. Wiring: `crates/luabox-cli/src/check_cmd.rs:398` `harvest_rocks` (path-keyed export registry, so a project file shadowing a rock module wins by resolution) and `crates/luabox-lsp/src/diagnostics.rs:101` (module-name-keyed, because the salsa db only holds project files; `or_insert` reproduces the same precedence).

- **opus-13c** (2026-07-29T23:25:00.000Z): **Perf finding, fixed mid-wave.** A synthetic 100-kLOC / 50-file *fully annotated* rock tree in front of a one-file project cost 1.98 s per `check` — the harvest was sequential while the source set was already on rayon. Split `harvest` into a pure per-file half (`rocks::harvest_file`) and an ordering fold (`RockSurfaces::fold`), so `check` parallelizes the expensive half and the fold alone fixes precedence; the LSP keeps the sequential convenience form for its one startup pass, and a test pins that the two agree. 1.98 s → 0.55 s on 4 cores. Realistic annotated rocks are a fraction of that; unannotated ones cost a read plus a substring scan.
- **opus-13c** (2026-07-29T23:25:00.000Z): **Honest limits, now written into the docs rather than left implicit** (README "Using dependencies", docs/03-reference/02-limitations.md:239, spec §3 and §5): an unannotated rock harvests to nothing; a library whose API is a *global* (LÖVE-style) still wants a defs package, because the harvest contributes declarations and export types but not ambient globals; and **argument checking at a rock function's call site does not happen** — `m.f("wrong")` after `local m = require("rock")` is unchecked. That last one is a **pre-existing checker gap for calls through any table or class field, project modules included** (verified against a plain project module and against an explicitly `---@type`-annotated receiver, both silent), not something the harvest introduced or could fix here — a def-declared global API like `geometry.point(…)` still *is* param-checked because it resolves as a dotted ambient function. Worth its own ticket. The rock's `---@return` types do flow, so misusing the result is caught, which is what the acceptance scenarios assert.
